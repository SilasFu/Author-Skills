## 2. 核心架构与代码质量硬门禁

所有在此仓库作业的 AI Agent 与开发者必须遵守以下刚性约束：

1. **单文件行数硬限制（≤ 200 行）**：
   - 业务与 UI 单文件严格控制在 **200 行以内**；
   - 超过 200 行必须按三层架构强制垂直切片：
     - `Component.tsx`：纯视图与 JSX 渲染层（无复杂业务状态）；
     - `useComponent.ts`：数据获取、状态衍生与副作用处理层；
     - `types.ts`：TypeScript 类型定义与数据契约。

2. **零黑盒私有记忆（Pure File-based SSOT）**：
   - 严禁依赖任何工具内部私有 Memory 或黑盒缓存；
   - 所有架构决策、需求变更与规范必须落盘于 Git 跟踪的文件中。

3. **视觉契约单一源（Single DESIGN.md）**：
   - 涉及界面与样式修改时，必须严格遵守 `DESIGN.md` 中的设计规范与语义 Token；
   - 严禁手写十六进制硬编码颜色（如 `#1e1e24`）或未受控的内联样式；
   - 界面状态必须完整覆盖 8 大状态（空状态、加载中、错误、部分加载、理想态等）。

4. **0 报错编译器硬门禁（Zero-Error Gate）**：
   - 代码编写完成后，必须执行原生类型检查与构建命令：
     ```bash
     {{CHECK_COMMAND}}
     ```
   - 编译器必须 **0 Errors / 0 Warnings** 才准交付。

## 3. 质量与架构禁忌 (Do's and Don'ts)

### 3.1 禁止事项 (Don'ts)
- ❌ 严禁生成大而全的单文件“巨石组件”；
- ❌ 严禁随意引入未经评估的重型第三方依赖库；
- ❌ 严禁出现 `any` 类型逃逸或未经处理的空指针。

### 3.2 推荐实践 (Do's)
- ✅ 优先编写具备高内聚、低耦合的原子化组件；
- ✅ 所有异步操作必须提供明确的错误捕获与用户反馈分支；
- ✅ 遵循 Conventional Commits 规范进行结构化 Git 提交。
