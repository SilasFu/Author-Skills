## ADR-001: 初始架构分层与质量门禁设定

- **日期**：{{INIT_DATE}}
- **状态**：✅ 已采纳 (Accepted)
- **涉及组件**：全局架构规范、`AGENTS.md`、`DESIGN.md`

### 1. 背景与问题陈述
在项目启动初期，为避免业务逻辑与视图耦合导致的“巨石代码”以及样式混乱，需要确立刚性的分层架构与质量门禁。

### 2. 备选方案评估
1. **方案 A（松散自由开发）**：不限制单文件行数，依赖人工 Code Review。
   - *缺陷*：极易迅速出现 >500 行的不可维护巨石文件与野样式。
2. **方案 B（三层垂直切片与严格行数门禁）**（**采纳**）：
   - 业务单文件严格 ≤ 200 行；
   - 视图、业务 Hook、类型契约三层垂直切片；
   - 编译器 0 报错作为提交门禁。

### 3. 决策后果
- **积极影响**：各模块职责极度清晰，新人/Agent 接手时认知负担极低；
- **需要注意**：拆分初期需要编写少量胶水代码与类型定义。
