# Author-Skills 架构决策记录 (Architectural Decision Records - ADR)

本文档完整记录 `Author-Skills` 仓库演进过程中产生的所有重大技术与治理决策。

---

## ADR-001: 确立元治理定位，剥离具体业务与 UI 轮子

- **日期**：2026-08-22
- **背景**：初期曾考虑自研任务拆解、特定框架 UI 生成或浏览器端到端标注等 Skill，但发现社区（如 Matt Pocock 等）已有大量成熟实现，重复造轮子导致维护成本过高。
- **决策**：`Author-Skills` **只专注于生态母体元治理（Meta-Governance Engine）**，即“机制建立、自我修正、自我改进”。所有业务逻辑、TDD 流程、特定框架 UI 美化等均按需消费社区公版 Skill。
- **收益**：仓库职责极度纯粹，聚焦于解决跨设备冷启动、架构防腐与规则自进化，代码量轻量可控。

---

## ADR-002: 通用开源框架与用户私有资产彻底解耦

- **日期**：2026-08-22
- **背景**：早期配置容易硬编码本地特定路径（如 `D:\MY_Memories`）或个人 GitHub 账号（`SilasFu`），导致新电脑单 C 盘或跨平台运行时直接崩溃，且无法安全开源分发。
- **决策**：
  1. `Author-Skills` 源码保持 100% 通用中立，零私密硬编码；
  2. 运行时通过 `/workspace-bootstrap init` 交互式引导用户绑定属于其自己的私有 Git 仓库；
  3. 全局寻址基于 `$env:AI_WORKSPACE_ROOT` 与 `$env:MY_MEMORIES_PATH` 环境变量自感知。
- **收益**：支持单 C 盘、D 盘、Mac/Linux 等任意环境，源码可安全开源分发给任何开发者使用。

---

## ADR-003: 建立双仓库分工（Author-Skills 源头 vs My-Skills 备份）

- **日期**：2026-08-21
- **背景**：本地安装了数十个来自不同来源的公版技能，如果全部混在一起，会导致自研技能被淹没、无法版本化维护。
- **决策**：
  - `D:\Vibe_Coding\Author-Skills`：唯一自研与定制源头仓库，遵循 `writing-for-agents` 严谨编写；
  - `D:\Vibe_Coding\My-Skills`：全量公版技能与场景元数据的只读备份仓库（Backup Warehouse），用于防丢失与追溯。
- **收益**：自研资产与外部引入资产物理隔离，权责分明。

---

## ADR-004: 基于 Git Commit 闭环的规则自进化与全生态免疫机制 (Evolve SOP)

- **日期**：2026-08-22
- **背景**：人类在与 Agent 协作时经常指出错误（如“不要用弹窗”、“单文件必须拆分”），但如果仅停留在聊天记录中，换会话或换 Agent 就会复发。
- **决策**：在 `project-guard` 中固化 `evolve` SOP。一旦捕获纠偏，自动提炼原子规则 ➔ 自动回写权威文件（`MY_Memories` 或 `AGENTS.md`）➔ 自动执行 Git Commit。
- **收益**：实现全生态、跨设备、跨 Agent 的“一次纠偏、全量永久免疫”，彻底消灭同类错误的重复出现。

---

## ADR-005: 以运行时构图契约治理视觉发布，不固化具体海报版式

- **日期**：2026-08-23
- **背景**：参考图驱动的封面与长图生产容易出现构图漂移、素材用途误判、自动水印混入和废稿残留。仅靠提示词难以稳定复现，直接把某套海报坐标写进仓库又会违反元治理边界。
- **决策**：新增 `visual-publishing-governance`，只固化资产角色分类、运行时构图契约、确定性排版、版式对比和交付审计机制。每个项目的尺寸、坐标、字体、文案、人物与品牌信息均由任务输入和经确认的锁版契约提供；仓库不保存个人身份信息，也不内置特定海报的固定布局。
- **收益**：在不引入特定 UI 轮子的前提下，把“一次参考图复刻”升级为可验证、可复用、可清理的视觉生产流程，并与 ADR-001 的元治理定位保持一致。
